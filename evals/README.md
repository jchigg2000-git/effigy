# evals

The committed evaluation harness. **Every number that appears in a document must
come from a file this wrote.**

It replaces the since-deleted `husk-api/scripts/fpe_corpus_eval.py`, which was `fpe`-only, printed
to stdout, saved nothing, and hardcoded corpus paths. That is why the previously
recorded results were not reproducible: they were transcribed by hand from a
terminal, and a later commit edited the corpus underneath them without anything
noticing.

## Layout

| Path | What it is |
| --- | --- |
| `preregistration.md` | **Frozen before the first run.** The RSCH-1 design, scoring rule, and pass/fail thresholds. Every run records this file's commit SHA. |
| `run_eval.py` | The runner. |
| `counters.py` | Regex structural counters (Go/TS/TSX). Not a parser; a reproducible proxy for "did the shape survive." |
| `corpus/manifest.json` | Corpus fingerprint — per-artifact sha256/bytes/lines/blob-oid, plus the authored `domains` block carrying `true_domain_id` and `leak_terms[]`. |
| `score_husk.py` | Scores a husked tree against its source: whole-file similarity, code-body verbatim rate (comments and docstrings excluded), and authored leak-term hits. Flags silent passthrough BEFORE any leak number is read. |
| `run_replicates.py` | Husks the same tree N times and reports mean + full range. The acceptance gate for prompt changes: a single run cannot separate a real effect from a resample. |
| `calibrate_postcondition.py` | Fits the request-path passthrough gate's thresholds against every husk on disk, by calling the shipped gate rather than a copy of its rule. |
| `leak_terms.json` | **Authored** leak-term lists, one per source domain. Never derived from a husk. |
| `blind_stub.py` | The BLIND arm's structural stubs (§3). Generated by code, never hand-written, and re-checked content-free before release — a BLIND item that is not blind would silently turn the baseline into a second husk arm. |
| `run_rsch1.py` | **The RSCH-1 runner.** Two resumable stages: `--stage artifacts` builds every arm's artifact (the expensive half — 3 husks per source), `--stage attack` runs the attacker panel over the cache. Refuses to run against a corpus with fewer than 6 source domains. What a resume does again, and what it records, is below. |
| `score_rsch1.py` | **The RSCH-1 scorer.** Validity gate first, then the deterministic leak-term pre-check, then the judge, then verdicts. Wilson intervals and a cluster bootstrap over *source files*. Also reports coverage against the full expected job set, calls a gate with no source arm NOT EVALUATED rather than failed, applies A1's three-domain floor, lets §8's hard veto reach the verdict table, flags an `llm-translation` arm whose recorded gate state does not match it, and sums token usage in §7 (not pre-registered). |
| `prompts/` | The attacker briefing (§4 Kerckhoffs), forced-choice (§6.1), open-ended (§6.2) and judge prompts. Each carries a leading HTML-comment design note that `load_prompt()` strips before the text reaches a model. |
| `kappa_judge.py` | Cohen's κ for the judge (§6.2). `--sample` writes a blinded worksheet (no judge label, no artifact), `--score` computes κ. Below 0.6 the judge table is descriptive only. Records are matched on (item, attacker); `--sample` refuses to overwrite a worksheet that already carries labels. |
| `verify_domains.py` | The mechanical acceptance gate for `corpus/DOMAINS.md` §5 — file count, line envelope, `gofmt -e`, TS1xxx syntax, path escapes, cross-domain vocabulary bleed, and `leak_terms` size/disjointness. |
| `run_models.py` | Model selection sweep for `llm-translation`: which backend preserves code structure. |
| `probe_models.py` | Probes every model in the shipped catalog for reachability at the configured endpoint. |
| `run_smell_loop.py` | The diagnostic-validity loop: does a husk still smell the same? |
| `husk_tree.py` | Husks the whole corpus tree with one model, preserving directory structure, so repository-level defects stay visible to a multi-file reviewer. |
| `husk_paths.py` | Husks the file paths of an already-husked tree and makes its imports resolve; writes `_path_map.json` (gitignored) beside the tree. |
| `canonicalize.py` + `canon/` | The RSCH-1B canonicaliser (pre-registration A4): strips identifiers, strings, comments and JSX text from one Go or TS/TSX file. `canon/canon_go` is a gitignored binary — build it with `(cd evals/canon && go build -o canon_go ./canon_go.go)`. |
| `structure_probes.py` / `structure_probes.json` | Model-free probes of the canonicalised artifacts (RSCH-1B); the JSON is the script's committed output, generated before the 2026-09-26 gate fix (see below). |
| `permutation_baseline.py` | Permuted-null correction for attacker answer bias; folded into `score_rsch1.py` §2b. p is (b+1)/(m+1); a cell whose files all carry one domain is reported as not computable. |
| `domains.json` | The six declared source domains; read by `run_rsch1.py`, `kappa_judge.py` and `verify_domains.py`. |
| `tests/` | Offline pytest suite for the runner, scorer and canonicaliser — see *Tests* below. |
| `runs/` | One directory per run. Layout depends on which script wrote it — see below. |

`run_eval.py` writes `runs/<utc-stamp>-<solution>-<backend>/` with `config.json`, one JSON record
per case and raw husks under `husks/`; **no committed run was produced by it.** The committed
directories were written by `run_rsch1.py` (`*-rsch1-held-out/`: `config.json`, `artifacts/`,
`raw/`, then `scored.jsonl` and `summary.md` from `score_rsch1.py`; abandoned attempts keep what
was written plus a `DISCARDED.md`; a resume since 2026-09-26 can also write `raw_superseded/` and
`artifacts/*.attemptN.error.json`, described below), `run_smell_loop.py` (`*-smell-loop/`: `config.json`,
`cases.jsonl`, `husks/`, `summary.json`), `probe_models.py` (`*-model-probe/`: `probe.json`, plus
`PANEL.md` where a panel was chosen), and — for the four `20260819-*` directories — by hand or by
`run_replicates.py` / `score_husk.py` / `calibrate_postcondition.py`, each carrying its own
`RESULT.md` or JSON write-up.

## Usage

    python3 evals/run_eval.py --refresh-manifest     # regenerate the corpus fingerprint
    python3 evals/run_eval.py --verify               # re-hash corpus + check pathology anchors
    python3 evals/run_eval.py --run fpe --crumb-level 1

    python3 evals/husk_tree.py --model <id> --target <target_id> --src <dir> --out <dir>
    python3 evals/score_husk.py --src <dir> --husk <dir> --terms electric-transmission

    # RSCH-1, the pre-registered re-identification experiment
    python3 evals/verify_domains.py                                  # gate the corpus first
    python3 evals/run_rsch1.py --stage artifacts --split held-out    # build every arm (slow)
    python3 evals/run_rsch1.py --stage attack    --split held-out    # run the panel
    python3 evals/score_rsch1.py evals/runs/<run-id>                 # gate, score, verdicts
    python3 evals/kappa_judge.py --sample evals/runs/<run-id>        # then hand-label, then --score

    # offline tests, from the repo root
    husk-api/.venv/bin/python -m pytest -q evals/tests

## Tests

`evals/tests/` holds 20 offline tests of the runner, the scorer and the canonicaliser. No test
makes a network call: every model client is replaced by a stub, and where a test sets an endpoint
it is a closed local port. Run them from the repo root with the `husk-api` virtualenv, which has
pytest; `conftest.py` puts `evals/` on `sys.path`, the way the scripts import each other.

    husk-api/.venv/bin/python -m pytest -q evals/tests

Four of the 18 skip on a fresh clone: two need Node and `corpus/stacks/app/node_modules/typescript`
(`npm ci --prefix corpus/stacks/app`), and two need the gitignored `evals/canon/canon_go` binary and
`gofmt`. Each test fails on the code as it stood before the 2026-09-26 fix it covers.

| file | covers |
| --- | --- |
| `test_harness_gate_race.py` | each `llm-translation` arm keeps its own gate state under six worker threads |
| `test_harness_attack_resume.py` | a transport failure neither spends the §6.1 retry nor stays cached |
| `test_harness_resume_provenance.py` | a resume keeps the first `config.json`; gate refusals are kept and retried errors preserved |
| `test_harness_usage.py` | attempts record token usage as int-or-null, without changing scoring |
| `test_scoring_kappa.py` | each κ worksheet row shows its own attacker's guess and label |
| `test_scoring_permutation.py` | p = (b+1)/(m+1); a single-domain cell is not computable |
| `test_scoring_summary.py` | coverage, NOT EVALUATED gate, A1 floor, hard veto, gate-state banner, §2b note, §5, §7 |
| `test_canon_comments.py` | every comment is blanked, and the text-level G2 scan catches one spliced back |
| `test_canon_gate_false_positives.py` | regex flags, braces inside literals and a URL no longer fail the gate |
| `test_canon_import_paths.py` | G4 finds the module name inside a preserved import path |

## Resuming a run, and what a resume records

`run_rsch1.py --run-id <id>` resumes a run. Since 2026-09-26 (`LIMITATIONS.md` errata E1–E3):

- **`config.json` is written once.** A resume never changes the first invocation's fields. It
  appends an entry to the `resumes` list with its own settings (started_at, stage, arms, attackers,
  modes, attacker `max_tokens`, commit and dirty flag, rewriter) and a `drift` list of the fields
  that differ. A change of `--split` or `--attackers` is refused unless `--allow-config-drift` is
  passed, which is recorded as `drift_allowed`; other drift is warned about on stderr and recorded.
  A `--dry-run` resume checks drift and appends nothing. The committed runs predate this, so their
  top-level fields describe their last resume.
- **A failed artifact is built again — except a gate refusal.** A gated `llm-translation` husk the
  post-condition gate refused is a §12 datum and stays as recorded; `--retry-refused` builds it
  again. Any other error (transport, harness, gate-state mismatch) is retried by default. Before a
  retry the old error meta is renamed `artifacts/<key>.attemptN.error.json` and the new meta lists it
  under `prior_errors`. Error metas carry `error_type`.
- **An attacker call is asked again only if it was never answered or is owed its §6.1 retry.** Model
  responses and transport failures have separate budgets, two of each, so a transport error no
  longer spends the parse retry; a record left with one unusable response carries `retry_owed`.
  Before re-asking, the old record moves to `raw_superseded/<name>.<n>.json` and the new record lists
  it under `superseded`, carrying earlier attempts forward when the prompt is identical. The
  `[attack] N/M parsed` line counts only calls asked in this invocation.
- **Every `llm-translation` husk's gate state is checked.** The ungated arm is husked in a child
  process whose own environment switches the gate off; nothing edits the runner's environment. After
  each husk the recorded `postcondition.thresholds` and `retries_allowed` must equal what the arm
  expects, or the husk is recorded as a `GateStateMismatch` error and never attacked. The gated arm
  refuses to start if a gate-off override is already set, and a refusal in the ungated arm is a
  harness error.

`raw_superseded/` and `*.attemptN.error.json` match none of the globs the scorers read (`raw/*.json`,
`artifacts/*.meta.json`, `artifacts/*.txt`). `run_models.py`, `run_smell_loop.py` and `husk_tree.py`
now pass the model per call (`options.model`) instead of setting `LLM_MODEL` from worker threads.

## Token usage

Every model call made by the scripts below records `usage`: `prompt_tokens`, `completion_tokens`,
`total_tokens` and `reasoning_tokens`, each an int or null. `usage` itself is null when the
provider sent none or the call raised; absence is not zero.

| script | where |
| --- | --- |
| `run_rsch1.py`, attack | `attempts[*].usage` and `attempts[*].max_tokens` in each raw record |
| `run_rsch1.py`, artifacts | `solution_meta.usage` (summed over post-condition attempts), `usage_attempts` and `postcondition.retries_allowed`; a refusal's error meta carries `usage` |
| `score_rsch1.py`, judge | `usage` in each judge record; summary §7 sums it per (attacker, arm) |
| `probe_models.py` | `usage` on each `probe.json` row |
| `husk_paths.py` | `mapping_usage` in `_path_map.json` |
| `run_smell_loop.py` | `husk_usage` and `diagnose_usage` per case; `baseline_usage` in `config.json` |

`run_models.py` and `husk_tree.py` call the rewriter but still discard its meta, so their usage is
not persisted. The committed runs predate this for attacker and judge calls, which record latency
only; their artifact metas do carry the rewriter's final-attempt `solution_meta.usage`, which
`score_rsch1.py` §7 now sums as a rewriter row. The OpenAI client still retries twice underneath,
and those retries are not recorded separately.

## Commit references under `evals/runs/` do not resolve

This repository is published as a **single root commit**. Each run's `summary.md` records a
`Pre-registration commit:` and a `Repo commit:` SHA, per the pre-registration's §12 rule 4 — those
identify the pre-publication history and **will not resolve here**. They are left exactly as
recorded rather than edited, because they are the provenance the pre-registration asked for and
rewriting them would falsify it. What they pinned is unavailable to a reader of this repository;
what each run actually measured is fully contained in its own directory — config, raw responses,
scored records and the summary that reports them. The same applies to every other commit SHA under
`evals/runs/` — the commit fields in each `config.json`, and the fix commits cited in
`DISCARDED.md`, `RESULT.md` and `baseline_real.json` — and to the SHAs in `ROADMAP.md`,
`DECISIONS.md` and `algorithmTests.md`.

## A fresh clone skips the TypeScript parse gate

`verify_domains.py` shells out to the `tsc` in `corpus/stacks/app/node_modules`, which a fresh
clone does not have. The gate reports those checks under **SKIPPED** — not as failures — and exits
0 if everything that could run passed. To enable it:

    (cd corpus/stacks/app && npm install)

Go parsing, self-containment, cross-domain bleed and the leak-term gates all run without it.

## `canonicalize.py --all` gates every corpus artifact

`python3 evals/canonicalize.py --all` shells out to `evals/canon/canon_go`, a gitignored binary a
fresh clone must build first — `(cd evals/canon && go build -o canon_go ./canon_go.go)` — and to
`evals/canon/canon_ts.mjs` under Node. With both in place **all 64 corpus artifacts pass the gate**,
in both arms (`--nonum` too).

**Corrected 2026-09-26** (`LIMITATIONS.md` erratum E12). This section used to say that
`corpus/stacks/api/internal/ingest/marc21.go` fails gate G8 (`max_brace_depth` 7 → 6) because "the
canonicaliser loses one level of nesting on that file", and that `--all` was expected to be red.
The canonicaliser was right and the gate was wrong: the raw depth of 7 comes from the string literal
`"{dollar}"` on line 140, and `counters.py` counts braces inside literals, as it says it does. With
literals and comments masked, the source and the canonical output both nest 6 deep. G8 now compares
brace depth on the masked code, and records a difference that comes only from literals in
`blind_delta` instead of failing. The section also called `corpus/stacks` "not an RSCH-1 domain"; it
is `library-circulation`, in the selection split. RSCH-1B attacked only held-out files, so no
attacked artifact was affected; the model-free tokens probe in `structure_probes.json`, which ran
over all 64 files, was (n = 63; `LIMITATIONS.md` E12).

`evals/structure_probes.json` has not been regenerated. It still lists `marc21.go` under
`gate_failures` and ran its tokens probe on n = 63; regenerated, that probe would read 0.000 against
a 0.156 null (n = 64), and the counters probe would not change.

The same day's other gate changes: the TS classifier now blanks a comment whose next token is `)`,
`]` or `}`, including a JSX `{/* */}` (8 of the 60 committed RSCH-1B artifacts kept one; erratum
E10, the artifacts are left as run); G2 adds a text-level closed-world scan of the whole output, so
a lexer blind spot can no longer be shared by the transform and its gate; G2 accepts regex flags;
G11 counts the source's comments with the lexer instead of searching for `//`; and G4 searches
preserved import paths for the module name. Still open: a local that shadows an import name keeps
the member names selected on it (needs object resolution in `canon/canon_go.go`), a leaked comment
made only of preserved tokens passes the text scan, and a Go file whose only string literals are
import paths fails G11.

## Two leak-term lists, and they are not interchangeable

`leak_terms.json` is matched against **husk source lines** by `score_husk.py`, so it is correctly
identifier-shaped. The `domains[].leak_terms` block inside `corpus/manifest.json` is matched
against the **attacker's free-text guess** by RSCH-1 (§6.2 pass 1), so it is natural-language
vocabulary. Putting an identifier list in the second one would be dead weight that can only make
the §8 hard veto fire *less often* — an error in the flattering direction. See the manifest's
`_provenance` field.

## Three properties worth knowing

**Results are self-describing.** Each record embeds its input's own sha256 plus
the corpus commit, so you can always tell which bytes produced a number without
trusting a document.

**Drift is detectable.** `--verify` re-hashes every corpus artifact against the
manifest and re-checks that every `PATHOLOGY.md` symbol anchor still resolves.
The anchors are symbols, never line numbers — line numbers drift the first time
anyone touches a file, which is how the superseded corpus rotted.

**The harness refuses to persist a re-identification map.** `fpe` and
`literal-tagging` place that map into `meta` when `options.emit_map` is set, and
this harness calls `husk()` directly, so a naive `json.dump(meta)` would commit a
full pseudonym→original map of the corpus. `assert_no_map()` runs before every
write and exits hard. Never set `emit_map` here.

## Raw outputs are committed on purpose

A results table with no raw outputs is indistinguishable from a fabricated one —
which is precisely the credibility problem this repository is trying to solve for
itself. If a run is discarded, the reason is recorded and the discarded output
stays committed.
