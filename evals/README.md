# evals

The committed evaluation harness. **Every number that appears in a document must
come from a file this wrote.**

It replaces the since-deleted `husk-api/scripts/fpe_corpus_eval.py`, which was `fpe`-only, printed
to stdout, saved nothing, and hardcoded corpus paths. That is why the previously
recorded results were not reproducible: they were transcribed by hand from a
terminal, and a later commit edited the corpus underneath them without anything
noticing.

## Layout

| Path | What it is |
| --- | --- |
| `preregistration.md` | **Frozen before the first run.** The RSCH-1 design, scoring rule, and pass/fail thresholds. Every run records this file's commit SHA. |
| `run_eval.py` | The runner. |
| `counters.py` | Regex structural counters (Go/TS/TSX). Not a parser; a reproducible proxy for "did the shape survive." |
| `corpus/manifest.json` | Corpus fingerprint — per-artifact sha256/bytes/lines/blob-oid, plus the authored `domains` block carrying `true_domain_id` and `leak_terms[]`. |
| `score_husk.py` | Scores a husked tree against its source: whole-file similarity, code-body verbatim rate (comments and docstrings excluded), and authored leak-term hits. Flags silent passthrough BEFORE any leak number is read. |
| `run_replicates.py` | Husks the same tree N times and reports mean + full range. The acceptance gate for prompt changes: a single run cannot separate a real effect from a resample. |
| `calibrate_postcondition.py` | Fits the request-path passthrough gate's thresholds against every husk on disk, by calling the shipped gate rather than a copy of its rule. |
| `leak_terms.json` | **Authored** leak-term lists, one per source domain. Never derived from a husk. |
| `blind_stub.py` | The BLIND arm's structural stubs (§3). Generated by code, never hand-written, and re-checked content-free before release — a BLIND item that is not blind would silently turn the baseline into a second husk arm. |
| `run_rsch1.py` | **The RSCH-1 runner.** Two resumable stages: `--stage artifacts` builds every arm's artifact (the expensive half — 3 husks per source), `--stage attack` runs the attacker panel over the cache. Refuses to run against a corpus with fewer than 6 source domains. |
| `score_rsch1.py` | **The RSCH-1 scorer.** Validity gate first, then the deterministic leak-term pre-check, then the judge, then verdicts. Wilson intervals and a cluster bootstrap over *source files*. |
| `prompts/` | The attacker briefing (§4 Kerckhoffs), forced-choice (§6.1), open-ended (§6.2) and judge prompts. Each carries a leading HTML-comment design note that `load_prompt()` strips before the text reaches a model. |
| `kappa_judge.py` | Cohen's κ for the judge (§6.2). `--sample` writes a blinded worksheet (no judge label, no artifact), `--score` computes κ. Below 0.6 the judge table is descriptive only. |
| `verify_domains.py` | The mechanical acceptance gate for `corpus/DOMAINS.md` §5 — file count, line envelope, `gofmt -e`, TS1xxx syntax, path escapes, cross-domain vocabulary bleed, and `leak_terms` size/disjointness. |
| `run_models.py` | Model selection sweep for `llm-translation`: which backend preserves code structure. |
| `probe_models.py` | Probes every model in the shipped catalog for reachability at the configured endpoint. |
| `run_smell_loop.py` | The diagnostic-validity loop: does a husk still smell the same? |
| `husk_tree.py` | Husks the whole corpus tree with one model, preserving directory structure, so repository-level defects stay visible to a multi-file reviewer. |
| `husk_paths.py` | Husks the file paths of an already-husked tree and makes its imports resolve; writes `_path_map.json` (gitignored) beside the tree. |
| `canonicalize.py` + `canon/` | The RSCH-1B canonicaliser (pre-registration A4): strips identifiers, strings, comments and JSX text from one Go or TS/TSX file. `canon/canon_go` is a gitignored binary — build it with `(cd evals/canon && go build -o canon_go ./canon_go.go)`. |
| `structure_probes.py` / `structure_probes.json` | Model-free probes of the canonicalised artifacts (RSCH-1B); the JSON is the script's committed output. |
| `permutation_baseline.py` | Permuted-null correction for attacker answer bias; folded into `score_rsch1.py` §2b. |
| `domains.json` | The six declared source domains; read by `run_rsch1.py`, `kappa_judge.py` and `verify_domains.py`. |
| `runs/` | One directory per run. Layout depends on which script wrote it — see below. |

`run_eval.py` writes `runs/<utc-stamp>-<solution>-<backend>/` with `config.json`, one JSON record
per case and raw husks under `husks/`; **no committed run was produced by it.** The committed
directories were written by `run_rsch1.py` (`*-rsch1-held-out/`: `config.json`, `artifacts/`,
`raw/`, then `scored.jsonl` and `summary.md` from `score_rsch1.py`; abandoned attempts keep what
was written plus a `DISCARDED.md`), `run_smell_loop.py` (`*-smell-loop/`: `config.json`,
`cases.jsonl`, `husks/`, `summary.json`), `probe_models.py` (`*-model-probe/`: `probe.json`, plus
`PANEL.md` where a panel was chosen), and — for the four `20260819-*` directories — by hand or by
`run_replicates.py` / `score_husk.py` / `calibrate_postcondition.py`, each carrying its own
`RESULT.md` or JSON write-up.

## Usage

    python3 evals/run_eval.py --refresh-manifest     # regenerate the corpus fingerprint
    python3 evals/run_eval.py --verify               # re-hash corpus + check pathology anchors
    python3 evals/run_eval.py --run fpe --crumb-level 1

    python3 evals/husk_tree.py --model <id> --target <target_id> --src <dir> --out <dir>
    python3 evals/score_husk.py --src <dir> --husk <dir> --terms electric-transmission

    # RSCH-1, the pre-registered re-identification experiment
    python3 evals/verify_domains.py                                  # gate the corpus first
    python3 evals/run_rsch1.py --stage artifacts --split held-out    # build every arm (slow)
    python3 evals/run_rsch1.py --stage attack    --split held-out    # run the panel
    python3 evals/score_rsch1.py evals/runs/<run-id>                 # gate, score, verdicts
    python3 evals/kappa_judge.py --sample evals/runs/<run-id>        # then hand-label, then --score

## Commit references under `evals/runs/` do not resolve

This repository is published as a **single root commit**. Each run's `summary.md` records a
`Pre-registration commit:` and a `Repo commit:` SHA, per the pre-registration's §12 rule 4 — those
identify the pre-publication history and **will not resolve here**. They are left exactly as
recorded rather than edited, because they are the provenance the pre-registration asked for and
rewriting them would falsify it. What they pinned is unavailable to a reader of this repository;
what each run actually measured is fully contained in its own directory — config, raw responses,
scored records and the summary that reports them. The same applies to every other commit SHA under
`evals/runs/` — the commit fields in each `config.json`, and the fix commits cited in
`DISCARDED.md`, `RESULT.md` and `baseline_real.json` — and to the SHAs in `ROADMAP.md`,
`DECISIONS.md` and `algorithmTests.md`.

## A fresh clone skips the TypeScript parse gate

`verify_domains.py` shells out to the `tsc` in `corpus/stacks/app/node_modules`, which a fresh
clone does not have. The gate reports those checks under **SKIPPED** — not as failures — and exits
0 if everything that could run passed. To enable it:

    (cd corpus/stacks/app && npm install)

Go parsing, self-containment, cross-domain bleed and the leak-term gates all run without it.

## Known: `canonicalize.py --all` has one failing artifact

`python3 evals/canonicalize.py --all` shells out to `evals/canon/canon_go`, a gitignored binary a
fresh clone must build first — `(cd evals/canon && go build -o canon_go ./canon_go.go)` — and to
`evals/canon/canon_ts.mjs` under Node. With both in place it gates every corpus artifact and
**exits 1**: 63 of 64 pass,
and `corpus/stacks/api/internal/ingest/marc21.go` fails gate **G8** (`max_brace_depth` 7 → 6 — the
canonicaliser loses one level of nesting on that file). This is expected and does not affect any
recorded result: `corpus/stacks` is the pathology corpus, **not** an RSCH-1 domain, and the RSCH-1B
run canonicalised only held-out domain artifacts. The failure is recorded in
`evals/structure_probes.json` under `gate_failures`. Fixing the canonicaliser's brace-depth handling
on that file is open work; until then, `--all` is expected to be red.

## Two leak-term lists, and they are not interchangeable

`leak_terms.json` is matched against **husk source lines** by `score_husk.py`, so it is correctly
identifier-shaped. The `domains[].leak_terms` block inside `corpus/manifest.json` is matched
against the **attacker's free-text guess** by RSCH-1 (§6.2 pass 1), so it is natural-language
vocabulary. Putting an identifier list in the second one would be dead weight that can only make
the §8 hard veto fire *less often* — an error in the flattering direction. See the manifest's
`_provenance` field.

## Three properties worth knowing

**Results are self-describing.** Each record embeds its input's own sha256 plus
the corpus commit, so you can always tell which bytes produced a number without
trusting a document.

**Drift is detectable.** `--verify` re-hashes every corpus artifact against the
manifest and re-checks that every `PATHOLOGY.md` symbol anchor still resolves.
The anchors are symbols, never line numbers — line numbers drift the first time
anyone touches a file, which is how the superseded corpus rotted.

**The harness refuses to persist a re-identification map.** `fpe` and
`literal-tagging` place that map into `meta` when `options.emit_map` is set, and
this harness calls `husk()` directly, so a naive `json.dump(meta)` would commit a
full pseudonym→original map of the corpus. `assert_no_map()` runs before every
write and exits hard. Never set `emit_map` here.

## Raw outputs are committed on purpose

A results table with no raw outputs is indistinguishable from a fabricated one —
which is precisely the credibility problem this repository is trying to solve for
itself. If a run is discarded, the reason is recorded and the discarded output
stays committed.
