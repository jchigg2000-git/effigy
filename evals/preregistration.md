# Pre-registration — RSCH-1, adversarial source-domain re-identification

**Status: FROZEN. Committed before any run.**

This document fixes the experimental design, the scoring rule, and the pass/fail thresholds *before*
any data is collected. Every result directory records the commit SHA of this file, so a stranger can
check that the criteria were not adjusted after seeing the numbers.

**Amendments are appended, never edited in place**, and any amendment made after the first run must
say so and give its date. If you find yourself wanting to change a threshold to make a result read
better, that is the situation this file exists to prevent.

---

## 1. The claim under test

> **C1.** For source artifacts within the evaluated envelope (Go / TypeScript / TSX, single files of
> 40–400 lines, HTTP-service and SPA-component code), a husk produced by `llm-translation` does not
> permit a frontier-model adversary — one who knows the tool, the algorithm, the system prompt, and
> the target catalog — to identify the source's **problem domain** at a rate meaningfully above what
> the same adversary achieves from structural metadata alone.

Every qualifier is load-bearing. C1 says nothing about source outside that envelope, nothing about
adversaries with model internals, and nothing about the other two solutions (which are measured
anyway — see §5).

## 2. Why a single-domain corpus makes this unmeasurable

The superseded corpus was drawn entirely from one problem domain. Against it, an attacker that
ignores its input and always answers with that one domain scores 100%. Any recovery rate measured
that way is an artifact of the corpus, not a property of the husk.

**This experiment therefore requires K ≥ 6 distinct source domains**, each with a ground-truth label
fixed in the corpus manifest before any run. That requirement is the reason the corpus is being
rebuilt, and it is a precondition for this pre-registration being meaningful at all.

## 3. Arms

Four arms. Three of them exist to make the fourth interpretable.

| Arm | What the attacker receives | Role |
|---|---|---|
| **BLIND** | A structural stub *computed by the harness* from the source: language, line count, struct/handler/interface/import counts, max brace depth. No identifiers, no literals, no comments. | The floor **this attacker** reaches from priors and task framing alone. **This, not 1/12, is the baseline C1 is measured against.** |
| **SOURCE** | The unhusked source file. | **Validity gate.** If the attacker cannot identify the domain from the original, the task or the labels are broken and no verdict is issued for any arm. |
| **HUSK** | One husk, one arm per solution. | The measurement. |
| **COMPOSED** | `fpe(literal_tagging(src))`, chained by the harness. | The obvious reviewer question, at near-zero marginal cost. |

The BLIND stub must be **generated by code from the source file**, never hand-written, so it cannot
be tuned toward a flattering floor. Each BLIND item is paired with its HUSK items by source file and
uses the same menu-permutation seed.

## 4. Attacker knowledge — Kerckhoffs, deliberately

The attacker prompt includes the solution's full description, its configuration, and — for
`llm-translation` — the complete target-domain catalog. This repository is public: the realistic
adversary has all of it. Withholding it would produce a flattering number that the first skeptical
reader would dismantle in an afternoon.

The attacker is told explicitly that the artifact may have been rewritten into a *different* domain
and that it must identify the **original**.

## 5. Which artifacts are attacked — all of them, including the expected failures

`fpe` and `literal-tagging` are expected to leak at ceiling. They are measured anyway.

1. Marginal cost is one attacker call per husk; the husks are generated regardless.
2. The negative results are the most credible thing the paper can contain. "`fpe` leaks at ceiling
   because it passes comments and string literals verbatim; `literal-tagging` leaks at ceiling
   because identifiers survive; only `llm-translation` approaches the blind floor" is a stronger and
   more honest result than testing only the solution expected to pass.
3. The repo currently presents an `fpe` husk containing its source's import paths **as a success**,
   because that evaluation was scoring dependency reconstruction. Measuring it as a privacy failure
   and publishing the number converts the weakest artifact in the repo into evidence of rigor.

### Predictions, registered in advance

Recording these now means a predicted negative is a finding rather than an embarrassment.

| Arm | Prediction |
|---|---|
| `fpe` | ≈ SOURCE ceiling. Import paths and comments survive verbatim. |
| `literal-tagging` | ≈ SOURCE ceiling. Every identifier survives. |
| COMPOSED | Still well above BLIND. Comments survive **both** transforms. |
| `llm-translation` | ≈ BLIND floor. This is the only arm C1 is about. |

## 6. Scoring

Two separate calls per item. The menu is never shown in the same context as the open-ended question,
because seeing 12 options contaminates a free-text answer generated afterward.

### 6.1 Arm B — forced choice (**pre-registered primary endpoint**)

12 options: the K true source domains plus distractors to reach 12. Distractors are drawn from the
`llm-translation` target catalog, which makes them *hard negatives* — a husk translated into
`hotel-booking` will tempt an attacker toward `hotel-booking`, and picking the target instead of the
source is exactly the behaviour a working husk should produce.

Option order is permuted per item by a recorded seed, killing position bias. Scored by **exact match
against the ground-truth label — no judge, fully objective, fully reproducible.**

There is deliberately **no "cannot determine" option**: it muddies the denominator and lets a
cautious model hide a real capability. Instead every response carries a `confidence` float, and both
raw accuracy and accuracy-at-confidence ≥ 0.7 are reported.

Unparseable responses are retried once, then scored **incorrect**, with the parse-failure rate
reported separately.

### 6.2 Arm A — open-ended (**can only falsify C1, never support it**)

The attacker returns a free-text domain guess plus a `specific_identifiers` list of any
organization, product, regulation, or proprietary system it believes it can name.

`specific_identifiers` is the direct test of what the threat model actually cares about — *"the
organization, the product line, the proprietary algorithm, the regulatory domain"* — not merely "the
domain." A husk that scores at chance on a 12-way menu but names a real regulator in free text has
failed, and the menu's existence is irrelevant to that.

Scored in two passes:

1. **Deterministic pre-check, run first and reported separately.** Does the guess contain any term
   from that source domain's `leak_terms[]`, declared in the manifest before any run? No model, no
   judgement, fully reproducible. It will miss paraphrases; that is accepted.
2. **Judge model** — a third model family, distinct from both attacker and rewriter, temperature 0,
   **not shown the husk** so it cannot be swayed by it. Labels `MATCH` / `RELATED` / `MISS`. A random
   20% is hand-labelled and Cohen's κ reported. **If κ < 0.6, the judge numbers are reported as
   descriptive only** and only the deterministic pre-check counts as evidence.

Making Arm A one-sided removes any incentive to rationalize a judge disagreement into a pass.

## 7. Attacker panel — attacker ≠ rewriter, non-negotiable

- **A1 (primary):** a frontier hosted model from a different vendor family than the rewriter.
- **A2 (robustness):** a strong open model reachable through the configured router.
- **Judge:** a third model, different family from A1.

Three reasons this is not negotiable. **Threat-model fidelity:** the threat model puts the rewriter
in-tenant and the adversary at a third-party provider; one model in both roles collapses the two
parties the model exists to separate. **Self-consistency confound:** a model attacking its own output
can exploit its own habitual domain mappings, and the bias could run either direction — which is
precisely what disqualifies it. **Strength asymmetry:** the real adversary is a frontier model while
the rewriter is a quantized local model; pairing a weak attacker against a strong rewriter is the
standard way to manufacture a fake privacy result.

**The headline figure is the MAXIMUM `p_husk` across the panel, never the mean.** Averaging a strong
attacker against a weak one launders a failure.

## 8. Verdicts

**Validity gate, evaluated first. If it fails, no verdict is issued for any arm.**

- `p_source ≥ 0.90`
- Arm B parse-failure rate ≤ 5%

**Per solution, on Arm B:**

| Verdict | Condition |
|---|---|
| **PASS** | 95% CI upper bound on (`p_husk` − `p_blind`) ≤ 0.10 **AND** `p_husk` ≤ 0.25 |
| **FAIL** | (`p_husk` − `p_blind`) ≥ 0.25 **AND** CI lower bound > 0 |
| **INCONCLUSIVE** | anything else; or the validity gate fails; or the two attackers' `p_husk` differ by more than 0.20 |

**Hard veto from Arm A, overriding any Arm B verdict:** if the deterministic `leak_terms` pre-check
fires on ≥ 10% of open-ended guesses for a solution, that solution is **FAIL** regardless of its
forced-choice result.

**INCONCLUSIVE is reported as inconclusive** — never as support for C1, never as "no evidence of
leakage." That sentence is registered literally so it cannot be softened later.

## 9. Statistics

- **Wilson score intervals** for every proportion. The normal approximation is wrong at this n.
- **Cluster bootstrap** for the husk−blind difference: resample **source files** with replacement
  (10,000 draws), not items. Replicate husks of the same source are not independent observations, and
  treating them as such is the single most common error in small evals — it is what would make a
  PASS here indefensible.
- **No p-values.** They add nothing at this scale and invite fishing.
- **Per-domain accuracy is always reported.** One leaky domain is invisible in an aggregate and is
  exactly the case that matters.
- Exact counts are printed beside every rate (`4/24`, not just `16.7%`).

## 10. Trials and honest power

- Corpus: K ≥ 6 domains. Target 48 source artifacts.
- **Replicates:** the variance lives in the rewriter, not the attacker. `llm-translation` gets **3
  independent husks per source** (it is not byte-stable — 144 vs 159 lines on identical input at
  temperature 0.2). Deterministic solutions get 1.
- Attacker at temperature 0, one call per husk. Determinism is verified on a 20% subsample with 3
  calls each; if it does not hold, escalate to 3 attacker trials everywhere.

**Power, registered as a limitation rather than discovered later:** with ~48 clustered items this
design reliably resolves a difference of ~0.20–0.25 and **cannot resolve differences below ~0.10.**
A null result therefore means *"no leak detectable at this corpus scale"* — **not** that the husk is
private. That distinction is registered here so it cannot be blurred in the writeup.

## 11. What gets committed

Everything, including the raw model outputs. A results table with no raw outputs is
indistinguishable from a fabricated one — which is precisely the credibility problem this workstream
exists to solve.

- `evals/domains.json` — the 12-option menu
- `evals/corpus/manifest.json` — per artifact: path, hash, `true_domain_id`, `leak_terms[]`
- `evals/prompts/` — attacker (forced choice, open ended), judge, blind stub template
- `evals/runs/<utc-timestamp>/config.json` — model ids, temperatures, seeds, repo SHA, **and this
  file's commit SHA**
- `evals/runs/<utc-timestamp>/raw/*.jsonl` — full request and full response for every call
- `evals/runs/<utc-timestamp>/scored.jsonl`, `summary.md`

API keys are never recorded — `config.json` stores the base-URL host and model id only.

## 12. Anti-rationalization rules

1. Report at the **strongest** adversary tested, never the mean.
2. An inconclusive result is reported as inconclusive.
3. If a run is discarded, the reason is recorded in the run directory and **the discarded raw output
   stays committed**.
4. Every result table cites this file's commit SHA.
5. **Standing invitation:** if you break any of the falsifiers in `LIMITATIONS.md` §12, open an issue
   with the husk and the prompt, and it will be linked from that file.

## Amendments

### A1 — 2026-08-19, before any run: model selection is split off from confirmation

**Reason.** The project will recommend a specific backend model in its
publication, which requires comparing candidate models on the corpus. Choosing a
model by a metric and then reporting that same metric as evidence for C1 is
selection on noise, and §12 rule 2 already forbids the softer version of it.

**Amendment.** The corpus is partitioned **by source domain** into a
**selection split** and a **held-out split**, deterministically from the
manifest (sorted domain ids, alternating), so the partition cannot be quietly
re-drawn to favour a result.

- **Model selection** (`evals/run_models.py`) runs on the **selection split
  only**. Its outputs are *selection results* and are reported under their own
  heading. They are never cited as support for C1.
- **The confirmatory RSCH-1 run** uses the **held-out split only**, against
  which the chosen model has never been scored.
- Partitioning is by domain rather than by file because files within one domain
  are not independent observations — a file-level split would leak the selection
  set into the held-out set.
- If the held-out split ends up with fewer than 3 domains, the confirmatory run
  is reported as **INCONCLUSIVE** on power grounds regardless of its numbers.

**Model ranking rule, registered here so it cannot be tuned afterward.** Two
gates, then a ranking — never a weighted composite:

1. **Reliability gate** — the model must return usable code. Empty output,
   transport failure, or reasoning-block text reaching the output disqualifies
   the case. (The shipped solution strips code fences only, so a `<think>` block
   lands in the husk verbatim. That is measured as a failure, not silently
   cleaned, because cleaning it here would hide a real defect in the service.)
2. **Fidelity gate** — structural counters must survive within tolerance.
3. **Rank survivors by leakage** — mean source-domain `leak_terms` reaching the
   output, ties broken by median latency.

The gates come first because **a model that emits nothing leaks nothing** and
would top any leakage-ranked table. Privacy is only meaningful conditional on
utility, and a ranking that does not encode that is trivially gameable by a
broken model.

A model that fails either gate is reported with its failure mode and is not
assigned a score.

### A2 — 2026-08-19, before any run: model selection ranks on code structure, not domain leakage

**Reason.** A1 registered the selection ranking as "rank survivors by leakage."
That is a **data-masking** criterion applied to a **code-masking** problem.
Effigy husks source code so an LLM can review its *architecture*; the technique
fails if the rewrite destroys the architecture, so the question that decides
which backend to recommend is which one preserves program shape. Whether a husk
leaks its source *domain* is a property of the technique rather than of the
backend, and it is already measured by the main experiment above.

**Amendment, superseding A1's ranking rule only.** A1's selection/held-out split
stands unchanged. The ranking becomes:

1. **Returned-code gate** — non-empty, and free of reasoning-block text. (The
   shipped solution strips code fences and nothing else, so a `<think>` block
   reaches the husk verbatim. Recorded as a failure rather than cleaned:
   cleaning it here would conceal a real defect in the service.)
2. **Parse gate** — the husk must still parse. Go via `gofmt -e`; TS/TSX via
   `tsc`, counting **only TS1xxx syntax diagnostics**, because the husk is
   compiled standalone and every unresolved import raises TS2xxx noise. A husk
   that does not parse is useless regardless of how closely its token counts
   match, and this is the failure mode that counter-comparison alone misses.
3. **Rank by structure score** — mean per-key relative error between input and
   output structural counters, inverted; 1.0 is perfect preservation. Ties
   broken by median latency.

`string_literals` and `bytes` are **excluded** from the score on purpose:
`llm-translation` is supposed to rewrite those, and counting them would penalise
a model for doing its job.

No model in the scoring loop — every step here is deterministic and re-runnable
from the committed husks.

**Scope.** Candidate models are a small, deliberately chosen set spanning
coder-vs-general, several families, and several scales — not the whole catalog.
The set and the reason for each entry are recorded in the run config. Any model
excluded by a screening pass is logged with its count, so a bounded run cannot
read as full coverage.

### A3 — 2026-08-19, before any run: three deviations, registered rather than discovered

All three are recorded **before the first run**, per the amendment rule at the top of this file.
Each one bounds the claim, and each is written here so that a reader who wants to attack the result
finds the attack already named.

#### A3.1 The attacker panel is the strongest reachable, which is not the strongest that exists

§7 calls for **A1 (primary): a frontier hosted model from a different vendor family than the
rewriter.** No Anthropic, OpenAI or Google API credential exists in this environment; the only
inference endpoint available is the HuggingFace router already configured for the rewriter. The
panel is therefore drawn entirely from that endpoint, and is recorded in
`evals/runs/20260819T173746Z-model-probe/PANEL.md`:

| Seat | Model | Family |
|---|---|---|
| A1 primary | `moonshotai/Kimi-K3` | moonshotai |
| A2 robustness | `deepseek-ai/DeepSeek-V4-Pro-0813` | deepseek-ai |
| Judge | `zai-org/GLM-5.2` | zai-org |

**What §7 still gets:** three distinct families, none of them the rewriter's (Qwen), so the
attacker ≠ rewriter requirement and the judge's third-family requirement both hold literally. A1 is
the largest and most expensive model the endpoint serves.

**What §7 does not get:** a Claude/GPT-class hosted model. §7's third reason for the panel —
*strength asymmetry*, that "the real adversary is a frontier model while the rewriter is a
quantized local model" — is therefore only partly satisfied. The rewriter is a 7B; A1 is far larger
than that, so the asymmetry runs in the right direction, but the gap to a true frontier adversary is
unmeasured.

**Consequence, and it is not optional phrasing:** a null result from this panel means *"not
recovered by the strongest attacker reachable on this token."* It does **not** mean "not
recoverable." Any writeup that drops the qualifier is misreporting this experiment.

#### A3.2 The attacker is shown file CONTENTS only — never the path, filename, or directory layout

Not specified in the original design, and material enough that leaving it implicit would be a
defect. **Registered choice: the attacker receives the artifact's bytes and its language, and
nothing else.**

Reason: `llm-translation` rewrites file *contents*. It does not rewrite paths, and does not claim
to — a husked tree keeps its directory layout, which is why `evals/husk_tree.py` preserves
structure on purpose. Handing the attacker `api/internal/ingest/marc21.go` would measure a channel
the tool never claimed to close, and would drive **every** arm including SOURCE to near-100%,
making the whole comparison vacuous.

**But withholding it is flattering to the husk, and that has to be said plainly.** In real use a
reviewer usually sees filenames. This experiment measures content leakage in isolation; the path
channel is real, is wide open, and is out of scope here. `LIMITATIONS.md` carries the same
statement, and no result from this run may be described as "the husk does not leak the domain"
without it.

#### A3.3 Five of the six corpus domains are syntactically valid but not buildable

`corpus/stacks/` builds and its tests pass. The five domains added to satisfy §2 — `qsolog`,
`meterworks`, `tremorline`, `loomshed`, `tailwatch` — carry no `go.sum`, no lockfiles, no tests and
no seed data. Their gate is **syntactic validity** (`gofmt -e` clean; no TS1xxx diagnostics), not a
green build. The contract is `corpus/DOMAINS.md`.

This is sound for *this* experiment specifically: the attacker is shown one file's contents (A3.2),
so buildability is invisible at the item level and cannot bias a comparison between domains. It is
**not** sound for the defect-detection evaluation, which reads `corpus/PATHOLOGY.md` and needs a
tree it can reason about as a system — that evaluation stays on `stacks` only, and these five must
not be quietly recruited into it.

A second, deliberate difference: the five new domains implement **invented local interchange
formats**, never real published standards. `stacks` implements a real one (MARC 21), and that is
already the corpus's single known worst case for re-identification (`LIMITATIONS.md` §2 — a
frontier model recovered "MARC 21 / library catalog" from parsing constants alone). Reproducing
that choice five more times would bake the worst case into the aggregate and make the headline
number a statement about public-standard parsers rather than about husking.

#### A3.4 `llm-translation` target selection is left at its shipped default

The service picks a target domain by hashing each input, so different source files land in
different target domains. `evals/husk_tree.py` pins one target per tree, but that exists for
*tree coherence* and is not what a single-file caller gets.

**Registered choice: the shipped hash-selected default, with the actual target recorded per husk.**
Measuring the pinned variant would measure a harness flag rather than the product. A pinned target
would also hand the attacker a free elimination — every artifact reading as the same domain makes
that domain obviously the target and never the source.

### A4 — 2026-08-19, **after the first run**: RSCH-1B, the structure-only arms and the permutation baseline

This amendment is made **after** RSCH-1's confirmatory run completed, and says so here as the
preamble requires. It does not alter RSCH-1's design, arms, scoring, or verdicts; those stand as
run. It registers a **new question** raised by RSCH-1's result, and the arms that answer it, before
any of those arms are built or run.

**Reason.** RSCH-1 found that copying does not explain the leak — mean copied-span share was 0.269
when the attacker was right and 0.276 when it was wrong, and `composed` re-identified at 100% while
copying 0.000 of its source. The domain survives a genuine rewrite. This project's premise is that
**architectural pathology must be preserved**. If the architecture is itself domain-informative,
then the thing the technique is required to keep is the thing that leaks — a tension in the bet
rather than a defect in the prompt — and RSCH-2's verifier cannot fix a leak that lives inside the
invariant it exists to enforce. That has to be known before the verifier is scoped.

#### A4.1 Every arm is reported as observed MINUS a permuted baseline

RSCH-1's accuracies are confounded by attacker response bias: the BLIND attacker answered
`ham-radio-logbook` on 26 of 29 items regardless of input, which is most of its "33.3% floor."
Subtracting `p_blind` from `p_husk` is only valid if both carry the same bias, and they do not.

**Amendment.** `evals/permutation_baseline.py` holds each attacker's answers fixed, permutes the
true labels 10,000 times, and reports the accuracy distribution that response bias alone produces.
Every arm is reported as **observed − permuted mean**, with the one-sided
`p = P(bias alone reaches observed)`.

- **Labels are permuted across SOURCE FILES, not items**, replicates carried with their file. §9
  resamples source files for the cluster bootstrap because replicate husks of one source are not
  independent; the same reasoning binds here. It also preserves the 10/10/10 domain marginal exactly.
- The permuted mean is cross-checked against the analytic expectation `Σ_d P(ans=d)·P(true=d)`.
- Records with no parsed choice are dropped as **missing**, matching §8's existing treatment.
- This is pure computation over already-committed raw output. It **retro-corrects RSCH-1's published
  numbers**, and that correction is applied to the shipped run rather than only to new arms.

Applied to RSCH-1: BLIND corrects to **+0.025 / +0.033 (p ≈ 0.39–0.41)** — the floor was response
bias almost in its entirety, and the 10-number structural stub carries no recoverable domain.
`llm-translation` corrects to **+0.439 / +0.479**; `source`, `fpe`, `literal-tagging` and `composed`
to **+0.668**. The husk−blind *difference* barely moves, so **RSCH-1's FAIL verdicts stand unchanged.**

#### A4.2 Two new arms: `structure-only` and `structure-only-nonum`

**The transform.** Each source file is mechanically canonicalised so that everything the *author*
chose is removed and everything the *language and platform* own is kept:

- Comments are **blanked, not deleted** — replaced by a content-free comment occupying the same line
  span. Deleting them would change the line count and comment density, both of which are structure
  this project elsewhere insists on preserving.
- String literals → `str_NNNN`; regex literals → `/str_NNNN/`; JSX text runs → a single placeholder.
  Multi-line literals keep their newline count.
- Rune/char literals map to **distinct** placeholders, so a `switch` over `'H'/'D'/'T'` keeps three
  distinguishable discriminants rather than collapsing to one.
- Identifiers → `ident_NNNN` / `Ident_NNNN`, numbered in first-appearance order, **case-class
  preserved**. Case is not cosmetic: Go has no `export` keyword and exportedness is capitalisation,
  and a leading capital is what distinguishes a TSX component from an intrinsic element. Lowercasing
  everything would make this arm carry *less* structure than BLIND on the `exports` field.
- The identifier map is **unscoped and text-keyed**. Two shadowed `err`s collapse to one name, which
  reproduces the source's token-identity relation exactly; a scope-aware renamer would *split* them
  and thereby add information the source did not contain.
- **Own-module imports are canonicalised; external ones are not.** An import path is external iff its
  first segment contains a `.` or it is Go stdlib; in TS, a bare specifier is external and a relative
  one is not. Own-module Go imports keep an explicit alias so the binding stays coherent and the
  import count (coupling) survives.
- Numeric literals are **preserved** in `structure-only`.

**The allowlist is the arm's entire scope statement**, so it is fixed here rather than in code
comments: Go's 25 keywords and ~40 predeclared identifiers, the blank identifier `_`, package
identifiers bound by non-own-module imports and the members selected on them; for TS, the ambient
globals that are never imported (`fetch`, `JSON`, `Math`, `Date`, `Promise`, `console`,
`encodeURIComponent`, `URLSearchParams`, …), the HTML intrinsic element names, and the standard
attribute names **only when they appear on an intrinsic element** — attributes on an authored
component are author-chosen and are canonicalised. The exact list is printed into every run record
and disclosed to the attacker per §4, and each artifact ships a **preserved-token census** so
"what did you leave in?" is a published table rather than an argument.

**This is not an invented rule.** It is verbatim the contract `llm_translation.py` already imposes on
the rewriter — *"The ONLY names that survive unchanged are the ones the language owns… Imports of the
input's OWN modules ARE renamed"*. The structure-only arm is **that contract executed deterministically
and perfectly**, which is exactly what makes it the right upper bound to compare the rewriter against.

**Governing principle for every judgement call: when in doubt, strip.** Over-stripping makes a null
result narrower in scope but still valid. Under-stripping makes a *positive* result invalid — and the
positive result is the one that re-scopes the project.

#### A4.3 Both arms run unconditionally, and the primary is declared now

`structure-only-nonum` is identical except that numeric literals are also canonicalised. It does
**not** map them to `0`: that would destroy the fact that `[1:9]`, `[9:15]`, `[15:23]` chain into a
contiguous fixed-width layout, confounding "numbers carried the domain" with "we broke the
structure." Instead every distinct numeric literal other than `0` and `1` maps to its
first-appearance index starting at 2, token kind preserved. The equality relation survives; the
values and their ordering do not.

**Registered choice: both arms run unconditionally.** `structure-only` is the **pre-registered
primary endpoint**; `structure-only-nonum` is a **pre-registered secondary, mechanistic** arm.

The rejected alternative is recorded because it is the tempting one: running `nonum` *only if* the
primary scores above baseline. That is a garden of forking paths — it looks harder in exactly and
only the direction that could rescue the project's claim. Declaring both in advance handles the
multiplicity by declaration and costs roughly one further $5–8 against RSCH-1's $43.

It also buys a **monotonicity check**: `nonum` must not score above `structure-only`. If it does,
either the pipeline is broken or the attacker is noise-dominated, and that must be reported rather
than explained.

#### A4.4 Predictions, registered in advance (per §5)

| Arm | Prediction |
|---|---|
| `structure-only` | At or near its permuted baseline. Stated plainly: **we expect architecture alone not to be recoverable**, because that is what the project's bet requires. |
| `structure-only-nonum` | At its permuted baseline, and **not above `structure-only`**. |

**Both interpretations are pre-committed here so neither can be authored after seeing the number:**

- **At baseline** → architecture carries no recoverable domain. The leak is vocabulary the rewriter
  missed, a fail-closed verifier is the right fix, and the central claim is intact.
- **Well above baseline** → preserving pathology necessarily leaks domain. The verifier cannot fix a
  leak inside the invariant it enforces, and `docs/working-paper.md`'s central claim must be
  **re-scoped before RSCH-2 is built**. This is the outcome that changes the project, and it is
  registered as such before it is observable.
- **Above baseline in `structure-only` but at baseline in `nonum`** → the signal is numeric constants
  (format offsets, field widths), not control-flow shape. That is a narrower and more fixable finding
  than "architecture leaks," and it must not be reported as the broader one.

#### A4.5 Three limits, registered rather than discovered

1. **A3.2 still binds.** The attacker sees contents only, never the path. That is flattering to every
   arm including these, and no result here may be stated without it.
2. **The ordering against BLIND is not "strict."** The canonicalised artifact is recoverable-superior
   to BLIND on ten of the eleven fields `blind_stub.profile` reports, but **`bytes` is not
   recoverable** — fixed-width renaming destroys mean identifier length, which is a weak
   vocabulary-correlated signal BLIND does carry. The two arms overlap rather than nest, and the
   claim is registered in that qualified form, then **proved per-file by a gate** rather than
   asserted. Against the deterministic husks the containment *is* strict, and citable from their own
   shipped disclosures. Against `llm-translation` no ordering is claimed at all: "no vocabulary"
   versus "a different domain's vocabulary" is not an ordering.
3. **The instrument parses; the product still does not.** `docs/handoffs/02` and `03` forbid AST use
   in the shipped solutions, which must accept arbitrary caller source in arbitrary languages.
   `evals/canonicalize.py` is a measuring device applied to 30 known files in two known languages,
   offline, whose errors are not recoverable downstream — a mis-tokenised span becomes a wrong
   scientific conclusion. `evals/verify_domains.py` already shells to `gofmt` and `tsc` as gates, so
   the repo has already drawn this line. `counters.py`'s "regex is fine because the same bias applies
   to input and output, and the quantity of interest is the DELTA" is correct **and does not
   transfer**: canonicalize.py *produces the artifact*, where bias does not cancel.

**Every artifact must pass a mechanical gate before any attacker sees it**, and the run stops if one
fails. The gate is closed-world — every word token in the output must be in the allowlist or match a
placeholder — rather than open-world against the source's identifier inventory, which by construction
cannot see anything that came out of a comment or a JSX text node. The full gate list lives in
`evals/canonicalize.py` and its results are recorded per artifact.
