## blind
No artifact content is provided to you at all. You will see only a **structural profile** computed
mechanically from the original file — counts of lines, functions, handlers or components, structs
or classes, interfaces or types, imports, exports and string literals, plus its maximum brace
nesting depth and its language. No identifier, literal, or comment from the file is included, and
the profile is generated by code so that nothing about its content can leak through it.

Answer from this profile, from your priors about what kinds of programs get written, and from the
framing of the task. A confident guess is expected of you even though the evidence is thin.

## source
The artifact is the **UNMODIFIED ORIGINAL SOURCE FILE**. No transform has been applied. This is a
control condition.

## fpe
Solution `fpe` — format-preserving encryption of identifiers.

Every identifier token of two or more characters is replaced with a deterministic, length-
preserving pseudonym under a keyed permutation. The same source token always maps to the same
output token (referential integrity), and distinct tokens map to distinct pseudonyms (injectivity).
Tokens are matched by the regex `[A-Za-z_][A-Za-z0-9_]+`.

**String literals and comments are passed through VERBATIM by design and are not protected at
all.** Import paths, URLs, SQL text, error messages, format strings and any literal data survive
into the output unchanged. Single-character identifiers are also spared.

## literal-tagging
Solution `literal-tagging` — string-literal and PII tagging with type-class placeholders.

Every string literal is replaced by a typed placeholder such as `<URL:n>`, `<PATH:n>`, `<MSG:n>`.
The same literal content maps to the same placeholder throughout the file, so deduplication and
coupling are preserved. Triple-quoted, double-quoted, single-quoted and backtick literals are all
matched.

**Identifiers, comments and code structure are untouched.** Every function, variable, type, field,
table and column name survives exactly as written in the original.

## composed
Solution `composed` — `fpe(literal_tagging(src))`, the two transforms above chained by the harness.
String literals are first replaced by typed placeholders, then every identifier is enciphered under
the format-preserving permutation. **Comments survive both transforms unchanged.**

## llm-translation
Solution `llm-translation` — whole-file rewrite into a different problem domain by a language model.

A local or hosted model is given the file and instructed to rewrite it into a target domain. The
system prompt is published; its instructions are, in summary: rename every module, package, class,
function, method, variable, parameter, field and constant; rewrite every string literal, comment
and docstring into the target domain; replace every acronym, data literal, proper noun, URL, file
path, table and column name; but **preserve the architecture exactly** — same control flow, same
function count and arity, same class hierarchy, same coupling, same dead code, same god-objects,
same dependency cycles, same comment positions and speech acts, same naming morphology, same
length. It is explicitly told not to fix bugs, remove duplication, or improve the code, because the
defects are the object of study. The only names it is told to leave alone are those the language
owns: keywords, builtins, standard-library symbols, and public third-party package APIs.

The target domain is selected from a **fixed public catalog of nine entries**, and for a given run
one target is pinned for the whole file. The complete catalog is:

  graph-traversal, tensor-pipeline, event-scheduler, chess-engine, recipe-manager,
  wildlife-tracker, logistics-dispatch, music-streaming, hotel-booking

**So if the artifact reads as one of those nine, that is almost certainly the TARGET the tool chose,
not the source you are being asked for.** Known weaknesses you may exploit: the rewrite is
prompt-enforced with no verifier, it is not byte-stable, and it has been observed to leave numeric
literals, and sometimes whole spans of the original file, unrewritten.

## structure-only
The artifact is the original source file with **every trace of the author's chosen vocabulary
mechanically removed, and its shape left exactly intact.**

Specifically, by a deterministic program with no model in the loop:
- Every identifier the author named — types, functions, methods, fields, parameters, variables,
  constants, packages — is replaced by `ident_NNNN` or `Ident_NNNN`, numbered in order of first
  appearance. Capitalisation is preserved, because in Go it carries exportedness and in JSX it
  distinguishes a component from a DOM element.
- Every string literal, template literal, regular-expression literal and JSX text node is replaced
  by `str_NNNN`. Character/rune literals are replaced by distinct placeholder characters, so a
  `switch` over three of them still has three distinguishable cases.
- Every comment is blanked to `// -`, occupying the same lines it did before, so comment position
  and density survive but no comment text does.
- Imports of the file's **own** module are renamed; imports of the standard library and of
  third-party packages are left verbatim, along with the members selected on them
  (`slog.Logger`, `sql.Open`, `http.StatusOK`, `useState`). HTML element and attribute names are
  also left verbatim where they appear on a plain DOM element.
- Numeric literals are left unchanged.

What is therefore fully preserved: control flow, call graph, function and method arity, nesting
depth, coupling between files, the standard-library and framework API surface actually used, the
number and position of every declaration, and the line count.

Note that `fmt.Errorf("str_0012", ident_0033)` is not an arity error — the format string's content
was removed, not its argument list.

An identifier or literal you see is a placeholder, never a name. Reason from the shape.

## structure-only-nonum
Identical to `structure-only` above, with one further step: **numeric literals are also
canonicalised.** `0` and `1` are left alone; every other distinct number is replaced by its
first-appearance index. Equal numbers stay equal — so a chain like `[1:9]`, `[9:15]`, `[15:23]`
still reads as a contiguous fixed-width layout — but the actual values, and their ordering, are
gone.
